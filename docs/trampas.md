# Trampas del entorno

*English: [en/pitfalls.md](en/pitfalls.md)*

Fallos silenciosos o engañosos del entorno de trabajo, una línea con fecha por trampa. El traspaso de cada tanda está en [traspaso.md](traspaso.md).

- **2026-11-07 · `pipeline_cache.db` envenenado:** un arranque que falla (p. ej. un benchmark de partido con equipos de Arrange sin datos cargados) puede dejar filas en `local/wiicompiled-mlb/build/UserData/Cache/pipeline_cache.db` que abortan **todos** los arranques siguientes en el hilo de pipelines (`aurora::gx::build_shader` → `Module::fatal`, visto con lldb), aunque el código esté bien. Arreglo: borrar las filas nuevas (`DELETE FROM pipeline_cache WHERE rowid > <última buena>`) o restaurar una copia. Antes de un arranque arriesgado, copia el archivo.
- **2026-11-07 · Riesgo de downgrade v2/v3 del guardado de Arrange:** con este parche, cualquier guardado con la opción de marcas O de uniformes activa migra el bloque `MLBARRMK` a la versión 3 en `0xD2E00`. Un runtime v2 antiguo que lea ese guardado ve el bloque como Invalid en `0xD3000` y, si guarda con cambios, pisa parte del v3 (se pierden las elecciones de uniforme). Es aceptable mientras v2 no esté ampliamente distribuido; una vez actualizado, no volver a un runtime anterior con esos guardados.
- **2026-11-14 · Real input al launcher desde una sesión en segundo plano:** `keybd_event` / `mouse_event` tras `SetForegroundWindow` no llegaron a la ventana SDL del launcher (Windows niega el primer plano a un proceso que no lo tiene; una pulsación puede ir a otra ventana). Para las pruebas de la ventana de actualización usa `WIICOMPILED_LAUNCHER_ACTION` o el traspaso directo de `Update.ps1`, no input real.
- **2026-11-14 · `Get-CimInstance Win32_Process` desde Python:** la salida de PowerShell sale en la página de códigos OEM y una ruta con `Ñ` (`D:\pruebas\Pelota Ñ`) rompe el decodificado UTF-8 (`stdout` = `None`). Pon `[Console]::OutputEncoding = [Text.Encoding]::UTF8` al principio del comando.
- **2026-11-14 · `Move-Item` de una carpeta con archivos abiertos:** en Windows PowerShell 5.1, si el renombrado falla porque otro proceso tiene un archivo abierto dentro, `Move-Item` intenta copiar y deja creada la carpeta de destino (vacía o a medias) antes de fallar. Un «deshacer» que luego mueve la carpeta original a ese destino la mete **dentro** (`Game\launcher\launcher`). Para mover carpetas del programa usa `[IO.Directory]::Move` / `[IO.File]::Move` (renombrado atómico, sin copia) y comprueba antes que el destino no exista (`tools/setup/Update.ps1`, `Move-Items`).
